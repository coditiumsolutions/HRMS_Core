S1. What the module does today

Payroll turns each employee's basic salary, active allowances, active deductions and an income-tax slab into one payslip per employee per month. Nothing else feeds it: attendance, leave, joining and leaving dates are not used (see F4).

S3. How one payslip is calculated

Code: PayrollCalculationService.GeneratePayslip. The same steps run for every entry point.

1 Period→2 Pick rows→3 Allowances→4 Gross→5 Deductions→6 Tax→7 Net→8 Save slip + lines

S3.1 Steps and formulas

#StepRule
1PeriodMonth name and year. Fails if a slip already exists for that employee and period. Any year 2000 to 2100 is accepted.
2Which rows applyAllowance/deduction must be active, started (effective date before the month ends), not ended (end date not before the month starts), and the frequency must match (S3.2).
3Each allowancePercentage: basic × % / 100. Fuel Allowance with type Fixed Amount: Amount. Fuel Allowance with type Quantity: FuelPrice × Quantity. Legacy fuel type: Amount if above 0, else FuelPrice × Quantity. Anything else: Amount × Quantity.
4GrossBasicSalary + sum of allowances. A missing basic counts as 0.
5Each deductionPercentage: gross × % / 100. Fixed: the stored amount. The total is rounded to 2 decimals (half away from zero); each line is rounded separately.
6Income tax (updated)Only if ApplyTax is yes. Tax year = payslip year if month is July or later, otherwise year minus 1. Annual taxable income = basic × 12 (allowances are not taxed; the base is still open, B17). Take the slab with the highest start not above that income. Annual tax = fixed amount + rate % × (annual income − slab start). Monthly tax = annual tax / 12, rounded to the rupee. No slab for that tax year means no tax and the payslip says so. Payslip TaxPercentage holds the slab (marginal) rate.
7NetGross − payroll deductions − tax. Not limited to zero (F9).
8SaveOne Payslips row (unlocked) and one PayslipDetails row per allowance, deduction and the tax, plus a text copy of the working in CalculationDetails.

S3.2 Frequency rules

FrequencyApplies in a month when
Monthlyalways (between effective and end date)
Onceonly the month that contains the effective date
Annualonly the same calendar month as the effective date, every year
Weekly, Bi-Weeklytreated as Monthly (HR has not defined them). The allowance and deduction forms still offer them (F10)

S3.3 Worked example (illustrative figures, not real data) (updated)

Basic 60,000. Allowances: Fuel by quantity, 100 litres at a FuelPrice of 280 (28,000); 10% of basic (6,000); fixed 5,000 × quantity 1. Deductions: 5% of gross; fixed 2,000. Tax year 2026-27.

Allowances      28,000 + 6,000 + 5,000        = 39,000
Gross           60,000 + 39,000               = 99,000
Deductions      5% × 99,000 = 4,950 ; fixed 2,000  = 6,950
Tax             annual income 60,000 × 12     = 720,000
                slab 600,000 to 1,200,000: 0 + 1% × (720,000 − 600,000) = 1,200 a year
                monthly 1,200 / 12            = 100
Net             99,000 − 6,950 − 100          = 91,950

A higher salary shows the fixed amount: basic 200,000 a month = 2,400,000 a year, slab 2,200,000 to 3,200,000: 116,000 + 20% × 200,000 = 156,000 a year, 13,000 a month. Deduction percentages still use gross while tax uses basic × 12, so the 39,000 of allowances is never taxed (F8, B17).

S4. Lifecycle and locking as built

No slip→ generate →Unlocked ("Payroll Pending")→ edit any allowance/deduction of that employee →Locked ("Payroll Generated")
  • A slip can be deleted while unlocked (lines go with it, no audit row). Re-running payroll then recreates it. That is the only way to "regenerate" (decision T4 is still open).
  • A locked slip cannot be deleted, edited or unlocked. There is no unlock path (decision B15 is still open).
  • Locking is not a deliberate step. It happens as a side effect of editing an allowance or deduction: every unlocked slip of that employee, for every month, is locked and an audit row is written. The service describes the lock as "so stale payroll cannot be paid", yet the Payroll Status screen calls locked "Generated" and unlocked "Pending". The two meanings contradict each other (F1).
  • There is no approval, no "paid" state, no payment date and no month-close.

S5. Findings

Tags: BUG wrong result or blocked work today; GAP missing behaviour; INCONSISTENT works but contradicts itself or duplicates.

F1Lock means two opposite thingsbug

Editing one allowance locks all of the employee's unlocked slips in every month, including old ones. Locked slips can never be deleted or fixed, so an edit made to correct next month's pay freezes last month's slip with the old figures. The status screen then reports those slips as "Payroll Generated".

PayslipLockService, AllowancesController.Edit, DeductionsController.Edit, PayrollController.PayrollStatus

F2One locked slip blocks "Run Payroll" for everyonefixed 2026-11-25

Fixed: the month-wide lock check is gone from /payroll/run and /payslips/new; all routes now use one set of rules (PayrollCalculationService.CheckEmployee). It was: /payroll/run stopped with "Payroll for this month is locked" if any slip in that month is locked, even though the other employees have none yet. A single allowance edit (F1) can therefore block the bulk run. /run/single and /generate/selected do not make this check, so the three routes behave differently. /payslips/new checks it again in a fourth way.

F3Adding or deleting an allowance/deduction does not touch existing slipsaudit part fixed 2026-11-25

Since 2026-11-26 an unlocked slip can be regenerated from its page (T4), which picks up such changes. Audit is now written for create, bulk create and delete of allowances and deductions, and for payslip delete and manual payslip create. Still open: only Edit locks slips, and Delete is a hard delete. Add an allowance after a slip is generated and the slip silently misses it; delete one and the slip keeps paying it.

F4Pay ignores attendance, leave, joining and leavingbug

Everyone gets the full basic regardless of join date, leaving date, absent days or unpaid leave. Employee.PayBasis and HourlyRate are not read, and the slip's working days, leave days, leave balance and hourly fields stay empty. Needs HR rules B6, B10, B11, B12 before it can be built.

F5Someone who resigned mid-month cannot get a final payslipbug

Every generation route and the status screen require EmployeeStatus = 'Active'. Employee History now sets Resigned or Terminated on a resignation, so once that is recorded the person can no longer be paid for the days worked that month. Joining month has the opposite problem (F4): full month paid.

F20Two rows of the same allowance stopped payroll for that employee and everyone after themfound and fixed 2026-11-26

Not in the original review. Line names are unique per payslip, so an employee with two Fuel Allowance rows could not be generated, and the failed save stayed queued, so every later employee in a bulk run failed too (524 of 848 on the development data). The second line is now named "... (2)" and a failure no longer affects the others. Whether a second row is valid is still B22.

F6No sanity checks before generatingpreview added 2026-11-25

New: Preview on the Run Payroll page (POST /payroll/run/preview) lists who would get a payslip and warns about no basic salary, future month, joined after or left before the month, tax switched on with no slabs, and negative net. Nothing is saved. The single and selected routes show the same warnings in their result message. Warnings do not stop generation (only "not Active" and "already exists" do); the date window for the month and proration wait for B21 and B10.

Any month from 2000 to 2100 is accepted, including future months and months before the employee joined. An employee with no basic salary gets a slip of 0.00. There is no preview and no list of warnings before the run.

F7Tax was a flat percentage of basic, not a progressive slab calculationfixed 2026-11-25

Was: the whole monthly basic multiplied by one slab percentage. Now: annual progressive method with a fixed amount per slab (see S3.1 step 6 and docs/reference/pk-income-tax.md). Still open under B17: whether allowances are taxable (the base), the 2025-26 fixed amounts (derived, to be verified against the Finance Act), and the 9% surcharge for 2025-26 incomes above 10 million (not applied). Script 12 has been run on production, so the fix goes live with the next deploy.

F8Percentage deductions use gross, tax uses basicinconsistent

Two bases in one slip (deductions on gross, tax on basic × 12). Might be intended (a provident fund on gross, tax on basic) but nobody has said so; part of B23 and B17.

F9Net pay can be negativewarns only

The preview and the run messages now warn about negative net pay; there is still no cap (B23). A fixed deduction larger than gross, or stacked loans, produce a negative net with no warning and no cap.

F10Frequencies and loan-style deductions are not really supportedgap

Weekly and Bi-Weekly are offered but behave as Monthly. A Monthly deduction runs until someone sets an end date; there is no total owed, no instalments and no remaining balance, so "Loan" and "Advance" types cannot stop themselves. The bulk deduction form only offers Once and Monthly, the single form offers all five.

F11Fuel price has no history and slips do not store quantity or ratefixed 2026-11-26

Fixed (T9): prices are kept with an effective-from date (Setup, Fuel prices), payroll uses the price on the 1st of the month, and slip lines store quantity and unit amount. Script 13 is on production; the app build is not deployed yet. It was:

One FuelPrice value in Configuration is read at generation. Change it and any slip generated afterwards, including a re-run of an old month, uses the new price. A slip line stores only the final amount, so it cannot later show "100 litres at 280".

F12Rounding is applied in some places and not othersinconsistent

Allowance lines and gross are unrounded; each deduction line and the deductions total are rounded separately, so the lines can differ from the total by a paisa. No rule for rounding net to whole rupees (decision B27).

F13Five ways to create a payslip, two payslip lists, two detail pagesmostly fixed 2026-11-26

Fixed (T10): one run page /payroll/run with a tick-box preview, one list /payslips, one detail page; old addresses redirect. Still open: the hand-typed /payslips/new stays until B20. It was:

/payroll/generate, /payroll/run, /payroll/run/single, /payroll/new and /payslips/new. The last one lets a user type gross and deductions by hand: no tax, no line items, no audit row, bypasses the engine. /payroll/new duplicates /run/single. /payroll and /payslips are two lists, /payroll/{id} and /payslips/{id} two detail pages. Views Payroll/Edit, Delete and Generate had no action behind them and were removed on 2026-11-25. Already noted in docs/routes.md as a behaviour decision.

F14Employee.GenStatus is stored text that goes stalefixed 2026-11-25

No route writes it any more and the two screens that showed it no longer do (the payroll search grid shows Locked / Unlocked from the payslip). The column stays in the database for a later clean-up.

Only the "select employees" screen writes text such as "Payroll Created for November 2026" (cut to 50 characters). Other routes do not, and the status screen already derives the real state from the payslips. The column adds nothing and can disagree.

F15No payroll reports, bank sheet or payment trackinggap

Only list, detail and print. No monthly summary by project or department, no bank transfer file, no tax withholding statement, no paid date. The Employee table has no bank details. See B26 and B28.

F16Anyone logged in can generate, view and delete payrollgap

Payroll controllers have no role check (known and deferred, B13). Payslip delete and manual payslip create write no audit row. Raised because salary data is the most sensitive in the system; I have not changed role checks.

F17Allowance and deduction catalogues are comma-separated text with names built into the logicgap

Names and types are CSV lists in Configuration. The calculation looks for the literal names "Fuel Allowance" / "Fuel" and the types "Quantity" / "Fixed Amount". There is no per-type flag for taxable, statutory or recurring. The database standard says lists with attributes should be tables. Also: employees 325 and 376 each hold two active Fuel Allowance rows and both are paid (B22).

F18AGENTS.md described a tax bug that had been fixedfixed 2026-11-25

The "Known payroll gotchas" note was out of date (tax year handling was fixed by T6) and has been rewritten for the annual slab method.

F19UI of the module has not had the redesignui

Done 2026-11-25: the fixed bottom action bar is replaced by the standard action bar (docs/ui_standards.md), and the sidebar emoji are Bootstrap Icons. Still open: the status grid is not on the Emp ID + name standard. To be done after the behaviour is settled so screens are not built twice.

S6. Proposed way it should work

Goal: one monthly payroll run that HR can preview, correct, approve and mark paid, with every figure explainable. Items marked * need an HR answer first (S7).

Open period→Preview with warnings→Generate drafts→Review / recalculate→Approve (lock)→Paid

P1One payroll run page per month, three payslip states* (fixes F1, F2, F13)

Draft (can be regenerated or removed), Approved (locked, only an Admin can reopen with a reason, logged), Paid (date and reference). Approval is a button, not a side effect of editing. Run for all, one department or one employee from the same page. Remove /payroll/new, /payslips/new and the orphan views; keep one list, one detail, one print. Decisions B20, B15, T10.

P2Who gets a slip is decided by dates, not just status* (fixes F5, F6)

Include an employee when joined on or before the month end and not left before the month start, whatever their current status. Preview lists who is included, who is excluded and why, and warns about: no basic salary, no tax flag set, period in the future, slip already approved. Decision B21 and B10.

P3Proration and attendance as separate, visible lines* (fixes F4)

Joining or leaving mid-month: a "Proration" line (method per B10). Later, unpaid leave, absent days and hourly days become their own lines fed from Attendance and Leave (B6, B11, B12, B16), so HR sees the reason for each reduction. Build after the rules are answered.

P4Changing an allowance or deduction marks Draft slips "needs recalculation" (fixes F1, F3)

Never silently locks. Draft slips for the affected months show a flag and can be regenerated in one transaction (T4); Approved slips are never touched, corrections go into the next run as an adjustment line. Create, edit and delete all write the audit row. Decision T11.

P5Tax method confirmed, then built properly* (F7, F8) (partly done 2026-11-25)

Done: annual progressive slabs with a fixed amount per slab, tax pages with year cards and a New tax year page. Still to decide (B17): the tax base (basic only today, or taxable gross with a taxable flag per allowance type), the 2025-26 fixed amounts, and the 2025-26 surcharge.

P6Slip lines remember how they were worked out (F11, F12)

Each line stores quantity, unit rate and a note ("100 litres × 280"). Fuel price is kept with effective dates so an old month recalculates correctly. One rounding rule applied the same way to every line and the total (B27).

P7Net floor and instalment deductions* (F9, F10)

A warning, and optionally a stop, when net would be below zero. Loans and advances get a total, an instalment amount and a balance that ends the deduction by itself. Weekly and Bi-Weekly are removed unless HR defines them. Decision B23.

P8Catalogues become tables (F17)

Allowance types and deduction types as managed lists under Setup → Lists, with flags (taxable, statutory, uses quantity, uses fuel price) so the calculation reads flags instead of names. Duplicate rows for the same allowance are flagged on entry (B22).

P9Reports and payment* (F15)

Monthly summary by project and department, a bank transfer sheet (needs bank details on the employee, kept off grids), tax withholding statement, and paid status. Decisions B26, B28. Salary figures stay off list grids.

P10Clean-ups that need no decision

Make all routes check the same rules (F2); audit payslip delete and allowance/deduction create/delete (F3); drop GenStatus writes (F14); fix the doc line (F18); apply the module redesign (F19).
